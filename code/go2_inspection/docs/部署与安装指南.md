# GO2 视觉巡检部署与安装指南

## 1. 本次可部署范围

当前工程已经把识别任务拆成五个互不依赖的小模块，统一配置位于
`configs/modules.json`：

| 模块 ID | 当前状态 | 当前行为 |
| --- | --- | --- |
| `tool_and_safety_sign` | 禁用 | 工具和安全标识牌清单未冻结，不训练、不推理 |
| `coal_presence` | 等待模型 | 只输出煤堆“有/无”；无检测模型时输出“不可用”，不会误报“无煤” |
| `station_number` | V1 可试运行 | YOLO 定位编号牌后，使用 63 张样本训练的模板模型读取 7～10 |
| `digital_meter` | 可试运行 | 已用 22 张例图训练初始模板模型，支持四位数、1 位小数、前导零和负号 |
| `analog_meter` | 禁用 | 缺少正常/异常参考图片，不训练、不推理 |

主流程的结果 JSON 在原有 `objects` 字段外新增 `modules` 字段。每个模块独立返回
`enabled`、`status`、结果和失败原因；单个模块失败不会中断其他模块或图片入库。

## 2. 部署前必须了解的准确率边界

数字表当前只有 22 张同一类型的例图，全部小数位都是 `.0`，而且数字类别极不均衡：
数字 `6` 和 `7` 各只有 1 个逐位样本。因此当前结果只能称为“初始可运行基线”。

- 对训练过的 22 张图片回归：22/22，100%。这个指标用于防止代码回退，不代表泛化。
- 按整张图片留一验证：19/22，86.4%。
- 逐位留一验证：85/88，96.6%。
- 留一验证错误：`999.0 → 995.0`、`060.0 → 080.0`、`075.0 → 035.0`。

程序已经按最坏情况预留：

- 任意 `0～9` 小数数字；
- 前导零；
- 负号独占一位或占用最高数字位；
- 单帧低置信度返回 `unreadable`，不强行猜数；
- 两帧或三帧输入时要求至少两帧读数一致。

编号牌 V1 当前支持 7～10，共 63 张有效样本；按原始文件留一验证准确率为 96.8%，
扰动留一验证为 81.2%。模块只在 YOLO 的 `station_marker` 框内读取，避免水壶等
蓝色背景物体干扰。其余 1～6 编号在补齐样本、重新训练和现场验证前不应启用。

但非零小数和负数目前只有合成测试，没有真实图片验证。正式现场使用前必须补拍。

## 3. 推荐部署环境

当前目标机器建议使用：

- Windows 10/11 64 位，或 Ubuntu 20.04/22.04 64 位；
- Python 3.12；
- 内存 8 GB 以上；
- 当前数字表模板模型只使用 CPU，不要求 NVIDIA GPU；
- 将来训练煤堆 YOLO 模型时，建议使用 NVIDIA GPU。

本工作区已验证的 GPU 环境是 RTX 5060 Ti 8 GB、PyTorch
`2.12.1+cu130`、Torchvision `0.27.1+cu130`。这不是数字表模块的必需条件。

Ubuntu 20.04/22.04 的完整安装流程见
[`Ubuntu20.04与22.04部署指南.md`](Ubuntu20.04与22.04部署指南.md)。

## 4. 第一次安装

以下为 Windows 命令，在 PowerShell 中执行。假设项目位于
`E:\视觉识别\code\go2_inspection`：

```powershell
cd E:\视觉识别\code\go2_inspection
python --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements-runtime.txt
```

如果 PowerShell 禁止执行激活脚本，可以不激活环境，直接使用：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-runtime.txt
```

安装开发测试依赖：


在与本机相同的 Windows/NVIDIA CUDA 环境中可安装：

```powershell
python -m pip install -r requirements-gpu-windows.txt
```

GPU 安装后检查：

```powershell
python -c "import torch; print(torch.__version__); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

## 6. 编号牌与数字表训练和评估

在项目目录执行：

```powershell
python .\scripts\train_station_number.py
python .\scripts\evaluate_station_number.py `
  --output ..\..\runtime_data\station_number\evaluation_current_samples.json

python .\scripts\train_digital_meter.py
```

编号牌训练默认输出：

- 模型：`E:\视觉识别\runtime_data\models\station_number_templates.npz`
- 训练及稳健性评估：
  `E:\视觉识别\runtime_data\station_number\training_metrics.json`

数字表训练默认输出：

- 模型：`E:\视觉识别\runtime_data\models\digital_meter_templates.npz`
- 训练及留一评估：
  `E:\视觉识别\runtime_data\digital_meter\training_metrics.json`

默认要求整串留一准确率不低于 80%，否则脚本以退出码 2 失败。这个门槛只是当前小样本
阶段的最低保护线，不是最终验收标准。

训练后执行回归评估：

```powershell
python .\scripts\evaluate_digital_meter.py `
  --output ..\..\runtime_data\digital_meter\evaluation_current_samples.json
```

每次新增图片时：

1. 把人工确认的真值写入文件名；编号牌例如 `8.png`，数字表必须保留完整格式，
   例如 `010.0.png`，不能写成 `10.png`；
2. 在对应样本配置中增加文件路径；配置标签必须与文件名一致；
3. 重新训练；
4. 检查留一验证错误，而不只看训练图片回归结果；
5. 只有新指标未下降并完成现场抽查后才替换生产模型。

### 多样本阶段训练

`configs/station_number_samples_staging.json` 会自动扫描
`样本/编号/<数字>/` 下的 JPG、JPEG 和 PNG。以后新增其它编号时，只需创建对应的
数字目录并放入样本，不需要逐张修改配置；质检不通过但需要保留的原图写入配置中的
`exclude` 数组。

V1 当前直接使用以下 7～10 阶段模型；`configs/modules.json` 的允许编号也限定为
7～10：

```powershell
python .\scripts\train_station_number.py `
  --samples .\configs\station_number_samples_staging.json `
  --model ..\..\runtime_data\models\station_number_templates_7_10.npz `
  --report ..\..\runtime_data\station_number\training_metrics_7_10.json

python .\scripts\evaluate_station_number.py `
  --samples .\configs\station_number_samples_staging.json `
  --model ..\..\runtime_data\models\station_number_templates_7_10.npz `
  --output ..\..\runtime_data\station_number\evaluation_7_10.json
```

训练报告同时给出训练集扰动指标和按原始文件留一验证指标。相邻连拍仍应视为同一采集
组；正式验收前还需要按采集批次建立独立测试集，不能只依赖留一验证。

## 7. 启动服务

```powershell
cd E:\视觉识别\code\go2_inspection
.\scripts\start_server.ps1
```

脚本监听 `0.0.0.0:8000`。本机检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json -Depth 6
```

正常情况下应看到：

- 服务 `status` 为 `ok`；
- `modules.station_number.status` 为 `ready`；
- `modules.digital_meter.status` 为 `ready`；
- 工具/标牌和指针表为 `disabled`；
- 煤堆在 YOLO 模型未配置时为 `unavailable`；

浏览器入口：

- 图片传输、参数调试与结果复核：`http://127.0.0.1:8000/ui`
- 接口文档：`http://127.0.0.1:8000/docs`
- 健康检查：`http://127.0.0.1:8000/health`

如果 GO2 从另一台设备访问，应使用上位机局域网 IP，例如
`http://192.168.1.20:8000`。Windows 防火墙或 Ubuntu `ufw` 中只应对可信局域网
开放 TCP 8000。

## 8. 数字表结果结构

一次抓拍最多上传 5 张图。数字表模块会返回类似：

```json
{
  "modules": {
    "digital_meter": {
      "enabled": true,
      "status": "confirmed",
      "raw_text": "010.0",
      "value": 10.0,
      "confidence": 0.72,
      "votes": 2,
      "reason": "multi_frame_majority_confirmed",
      "frames": []
    }
  }
}
```

业务侧应以 `raw_text` 展示读数，因为它保留前导零；`value` 只用于数值比较。
只有 `status == "confirmed"` 才能自动使用。`unreadable`、`unavailable`、`failed`
必须进入人工复核或重拍，不得当作 0。

## 9. 配置说明

模块开关：`configs/modules.json`。

应用路径、数据库和检测后端：`configs/app.json`。当前默认：

```json
{
  "detector": {
    "backend": "noop",
    "weights": null,
    "confidence": 0.35
  }
}
```

这意味着煤堆模型尚未加载。将来完成煤堆训练后才能改成：

```json
{
  "detector": {
    "backend": "ultralytics",
    "weights": "models/coal_presence_best.pt",
    "confidence": 0.35
  }
}
```

不要因为启用了数字表模块就提前启用指针表；两者是不同模块、不同数据要求。

## 10. 测试与升级验收

完整测试：

```powershell
python -m unittest discover -s tests -v
```

当前应通过 39 项测试。升级时至少检查：

1. 所有单元测试通过；
2. 编号牌稳健性和数字表留一训练门槛均通过；
3. 10 张编号牌与 22 张数字表现有样本回归无变化；
4. `/health` 中编号牌和数字表均为 `ready`；
5. 分别上传现场三连拍并检查 `modules.station_number` 和
   `modules.digital_meter`；
6. 模糊图、遮挡图应返回 `unreadable`，而不是错误的 `confirmed`；
7. 备份数据库和旧模型后再切换生产版本。

## 11. 常见故障

### 编号牌显示 `unavailable`

检查 `runtime_data/models/station_number_templates.npz` 是否存在，以及
`configs/modules.json` 的编号牌 `model_path` 是否正确。修复后重启服务。

### 数字表显示 `unavailable`

检查 `runtime_data/models/digital_meter_templates.npz` 是否存在，以及
`configs/modules.json` 的 `model_path` 是否正确。修复后重启服务。

### 数字表显示 `unreadable`

查看返回中的逐帧 `reason`。常见原因是未找到红色显示区、分割出的数字位数不是预期值、
单个数字置信度过低或多帧读数不一致。保留原图，不要手工改成 0。

### 中文路径图片读取失败

工程使用 Unicode 安全的字节解码方式读取 OpenCV 图片。若仍失败，先检查文件是否完整、
扩展名是否正确及运行账户是否有读取权限。

### 端口被占用

```powershell
Get-NetTCPConnection -LocalPort 8000
```

结束明确属于旧服务的进程，或修改 `scripts/start_server.ps1` 的端口。不要盲目结束未知进程。

### CUDA 不可用

当前数字表模块仍可在 CPU 上运行。只有煤堆 YOLO 训练/推理需要排查 NVIDIA 驱动、
PyTorch CUDA 版本和虚拟环境是否一致。

## 12. 下一批数据的最低要求

为了把数字表从“初始基线”推进到可验收版本，下一批优先收集：

- 每个数字 `0～9` 至少 30 个独立现场实例，尤其补足 `3、4、6、7、8、9`；
- 非零小数 `.1～.9`；
- 负数，包括负号独占位和负号占最高位（若设备支持）；
- 不同距离、角度、亮度、反光、轻微运动模糊；
- 缺段、遮挡、过曝、欠曝等应判为不可读的负样本；
- 同一读数不能只靠连续帧堆数量，应跨时间、跨角度采集。

收到这些数据后，应先冻结训练/验证/测试分组，再决定继续增强模板方案，还是替换为
CNN/CRNN。当前模块接口不需要因此改变。
