# GO2 视觉识别上位机：源码运行与工作台使用说明

正式部署环境：Ubuntu 22.04、RTX 4060、Python 3.12；Windows 10/11 可用于开发调试。
Windows 工作区已配置 Python 3.12 虚拟环境，可直接使用快速启动方式。
启动脚本会自动检查并同步缺失或已变更的运行依赖。
Ubuntu 首次安装见
[`Ubuntu20.04与22.04部署指南.md`](Ubuntu20.04与22.04部署指南.md)。

## 1. 快速启动

打开 PowerShell，执行：

```powershell
cd "E:\视觉识别\Coal Mine Identification\go2_inspection"
.\scripts\start_server.ps1
```

看到类似下面的内容表示服务已经启动：

```text
Uvicorn running on http://0.0.0.0:8000
```

在本机浏览器中打开：

- 图片传输与参数调试工作台：`http://127.0.0.1:8000/ui`
- 健康检查：`http://127.0.0.1:8000/health`
- API 文档：`http://127.0.0.1:8000/docs`

保持 PowerShell 窗口运行。需要停止服务时，在该窗口按 `Ctrl+C`。

如果 PowerShell 提示禁止运行脚本，先在当前窗口执行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

然后重新运行启动脚本。该设置只对当前 PowerShell 窗口有效。

Ubuntu 已完成首次安装时执行：

```bash
cd "/path/to/Coal Mine Identification/go2_inspection"
bash scripts/start_server.sh
```

安装完成后启动：

```powershell
cd "E:\视觉识别\Coal Mine Identification\go2_inspection"
.\scripts\start_server.ps1
```

### 2.1 使用 YOLO 模型时安装完整依赖

当前默认配置使用 `noop` 后端，只验证图片上传、存储、监控和结果复核，
不会产生目标检测框。

需要加载 Ultralytics YOLO 模型时安装完整依赖：

```powershell
cd "E:\视觉识别\Coal Mine Identification\go2_inspection"
.\.venv\Scripts\Activate.ps1

```

如果使用 Windows NVIDIA GPU 环境，可按项目锁定版本安装：

```powershell

```

Ubuntu 22.04 / RTX 4060 使用专用安装配置：

```bash
bash scripts/install_ubuntu.sh --profile gpu-4060
```

## 3. 配置识别模型

主配置文件为：

```text
E:\视觉识别\Coal Mine Identification\go2_inspection\configs\app.json
```

默认配置：

```json
{
  "detector": {
    "backend": "noop",
    "weights": null,
    "confidence": 0.35
  }
}
```

接入正式 YOLO 权重后，推荐继续以 `noop` 作为安全默认模式，只配置权重路径：

```json
{
  "detector": {
    "backend": "noop",
    "weights": "models/station_marker_best.pt",
    "confidence": 0.35
  }
}
```

`weights` 的相对路径以项目目录
`E:\视觉识别\Coal Mine Identification\go2_inspection` 为基准。修改权重路径后需要重启服务。
`backend` 决定“恢复默认值”后的推理模式；保持 `noop` 可以确保模型或显卡异常时
服务仍能启动并接收图片。

类别映射位于：

```text
configs\classes.json
```

模型输出的类别名称必须能在该文件中找到对应关系，否则会按模型原始名称输出。

## 4. 使用图片传输工作台

### 4.1 从 U 盘导入完整巡检数据

树莓派导出的目录必须保持完整结构：

```text
dataset_inbox\
  gas\
  thermal\
  visible\
```

每次导入前先清空 `dataset_inbox` 中上一批的三个数据目录，再把 U 盘根目录的
`gas`、`thermal`、`visible` 直接复制进来，不要只复制 `visible`。打开工作台后，
顶部“U 盘离线数据”区域会直接扫描这三个目录，不再需要额外的批次目录。

可见光目录支持两种格式：

- 当前树莓派格式：`visible\color_YYYYMMDD_HHMMSS_ffffff.jpg`，每张图片单独识别；
- 历史格式：日期目录下的三张图片和 `metadata.json` 抓拍包。

当前格式没有工位元数据，上位机不会补造或保存工位号；文件名中的本地时间按
UTC+08:00 解释，相机编号记为 `raspberry_pi_usb`。历史抓拍包仍使用自身元数据。

1. 点击“扫描收件箱”刷新目录；
2. 核对可见光抓拍、气体记录和红外热像数量；
3. 点击“导入并预检”；预检只登记文件和诊断信息，不运行视觉识别；
4. 核对预检结果后点击“确认并开始检测”，再通过进度条查看后台处理状态；
5. 检测结束后查看并按需人工修正，再点击“确认结果并开放报告”；
6. 报告确认后才显示下载入口；修正、重跑、删除或重试会重新锁定报告；
7. 存在坏包时修复文件并点击“重试失败项”，然后重新确认检测。

数据采用单工作线程逐包识别，关闭网页不会停止任务。上位机服务重启时，运行中的
已经确认且运行中的任务会自动恢复到等待队列，并跳过已经成功的抓拍；未确认任务绝不
会因服务重启而开始检测。程序根据三个目录中受支持文件的
相对路径生成内部批次编号；修复同名文件后可继续重试，清空并换入新时间戳文件后会
生成新编号。导入完成前不要增删目录中的文件。重复点击导入不会创建重复任务；同一
个 `capture_id` 若携带不同元数据或图片，会被标记为内容冲突。

气体 CSV 会解析为结构化传感器样本，同时兼容旧英文多列格式和当前
`时间、编号、CH4(%LEL)、O2(%VOL)、CO(ppm)、H2S(ppm)、状态` 七列格式。
气体和红外原文件会复制到：

```text
runtime_data\imported_batches\<batch_id>\
```

气体记录会结构化汇总；热像PNG携带 `thermal_stats_v1` 机器可读元数据，上位机使用
其中的整幅图最高温进行托辊卡死检测。最高温严格大于 65℃ 时判为异常，并关联前后
3 秒内最近的可信编号；同一编号的同类异常在首条报告后的 10 秒内不重复记录到报告，
但所有原始热像继续归档。缺失或损坏温度元数据的图片不做OCR猜测，统一标为需复核。
热像仍不包含原始 32×24 温度矩阵，因此若需热点区域定位或重新计算温度场，还要扩展
树莓派端数据格式。

### 4.2 手动上传图片

1. 打开 `http://127.0.0.1:8000/ui`。
2. 将 1～5 张 JPG、PNG 或 BMP 图片拖入上传区，也可以点击上传区选择文件。
3. 使用缩略图下方的左右按钮调整连拍顺序，使用“移除”删除图片。
4. 点击“上传并识别”。
5. 上传完成后，任务会自动出现在“最近巡检任务”中，并打开结果复核面板。

单张图片默认最大为 20 MB。一次上传的多张图片会作为同一个抓拍任务处理。

### 4.3 不提供 metadata.json

只选择图片时，网页会自动生成：

- 抓拍 ID；
- 当前 UTC 时间；
- 工位 `manual`；
- 相机 `browser_upload`；
- 空的机器人位姿。

这些字段只用于记录和输出，不会控制机器人。

### 4.4 附带 metadata.json

需要保留真实工位、相机和机器人位姿时，可点击“选择 metadata.json”。

示例：

```json
{
  "capture_id": "go2_station08_20260730_001",
  "capture_time": "2026-07-30T10:20:30+08:00",
  "station_id": "08",
  "robot_pose": {
    "frame": "map",
    "x_m": 1.2,
    "y_m": 3.4,
    "yaw_deg": 90.0
  },
  "camera_id": "go2_front",
  "images": [
    "frame_01.jpg",
    "frame_02.jpg",
    "frame_03.jpg"
  ],
  "batch_id": "route_001"
}
```

注意：

- `images` 必须包含 1～5 个文件名；
- `images` 数量必须与选择的图片数量一致；
- 文件名必须与所选图片对应；
- `capture_id` 只能使用字母、数字、点、下划线和短横线；
- 同一个 `capture_id` 重传时，元数据和图片内容必须完全一致。

工位和位姿在工作台中只读显示，不能通过网页修改。

## 5. 调整识别参数

工作台右侧提供以下运行参数：

- 推理模式按钮：`NOOP 仅记录` 与 `GPU 模型识别`；
- 检测置信度：过滤模型的低置信度目标；
- 三帧融合 IoU：控制多张连拍中同一目标的合并条件；
- 数字表单帧置信度：控制低质量数字表读数是否被接受；
- 工具/标牌、煤堆、工位编号、数字表和指针表模块开关。

### 5.1 切换 NOOP 与 GPU 模式

- `NOOP 仅记录`：保存图片、元数据和任务记录，不运行目标检测模型；
- `GPU 模型识别`：加载 `detector.weights` 指定的 Ultralytics 模型，并强制使用
  NVIDIA CUDA 设备 0 推理。

GPU 按钮只有在以下条件全部满足时才可用：

1. `configs/app.json` 已配置有效的 `detector.weights`；
2. 权重文件存在；
3. 已安装 Ultralytics 和 PyTorch；
4. PyTorch 可以检测到 NVIDIA CUDA 显卡。

点击按钮后立即热切换，不需要重启服务。切换期间新的识别任务会等待；如果模型加载
失败，系统会回滚到原模式。若服务重启时原 GPU 环境失效，系统会自动回退到 NOOP，
保证控制台仍能打开。

Ubuntu 正式上位机应检测到 `NVIDIA GeForce RTX 4060` 和 CUDA 12.6 PyTorch 环境。
若尚未配置有效 `.pt` 权重，GPU 按钮仍会显示不可用。

### 5.2 保存其他识别参数

调整后点击“保存参数”：

- 新上传的任务立即使用新参数；
- 正在执行的任务继续使用开始时的完整参数快照；
- 历史结果不会自动改变；
- 需要对历史任务应用新参数时，在结果面板点击“按当前参数重新处理”。

保存后的参数位于：

```text
E:\视觉识别\Coal Mine Identification\go2_inspection\runtime_data\runtime_settings.json
```

建议通过工作台修改参数，不要在服务运行期间手工编辑该文件。

点击“恢复默认值”会恢复项目配置中的默认参数，但不会自动重跑历史任务。

## 6. 监控和复核结果

“最近巡检任务”默认每 3 秒刷新一次，可关闭“自动刷新”。

支持：

- 按抓拍 ID 搜索；
- 按工位筛选；
- 按 U 盘离线批次筛选；
- 按识别中、已完成或失败筛选；
- 查看原始多帧图片和标注结果；
- 查看每个识别模块的状态；
- 查看本次处理使用的参数快照；
- 修改对象类型、类别、中文名称、置信度和边框坐标；
- 新增或删除识别对象；
- 使用高级 JSON 编辑；
- 记录操作人、修正原因和历史审计记录；
- 按当前模型和参数重新处理失败或历史任务。

人工修正不会覆盖原始模型结果。重新处理会停用旧修正，但不会删除审计历史。

## 7. 运行数据位置

默认运行数据位于：

```text
E:\视觉识别\Coal Mine Identification\go2_inspection\runtime_data
```

主要内容：

```text
runtime_data\
  database\inspection.db       # SQLite 任务和结果数据库
  incoming\<capture_id>\       # 接收到的原始图片和 metadata.json
  processed\<capture_id>\      # 标注结果图片
  evidence\                    # 证据文件
  imported_batches\<batch_id>\ # 已归档的气体 CSV 和红外 PNG
  runtime_settings.json        # 工作台保存的运行参数
  logs\                        # 运行或验证日志
```

备份时建议同时备份 `runtime_data`、模型权重和 `configs` 目录。

## 8. 局域网访问

启动脚本监听 `0.0.0.0:8000`。同一可信局域网内的其他设备可以使用上位机
IP 地址访问，例如：

```text
http://192.168.1.20:8000/ui
```

如果本机能打开、其他设备不能打开，请检查：

1. 两台设备是否在同一网段；
2. Windows 防火墙是否允许可信局域网访问 TCP 8000；
3. 使用的是否为上位机局域网 IP，而不是 `127.0.0.1`；
4. 路由器或交换机是否启用了客户端隔离。

当前服务没有登录鉴权，只应在可信实验室局域网中开放。

## 9. 检查服务状态

PowerShell 健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health | ConvertTo-Json -Depth 6
```

正常时顶层应包含：

```json
{
  "status": "ok",
  "detector": "noop",
  "detector_configured": false
}
```

`detector_configured: false` 表示当前没有加载正式检测模型，不代表上传服务故障。

## 11. 常见问题

### 11.1 页面无法打开

确认服务窗口没有退出，然后执行：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health
```

如果连接失败，查看启动窗口中的报错。

### 11.2 端口 8000 已被占用

检查占用进程：

```powershell
Get-NetTCPConnection -LocalPort 8000
```

也可以临时改用 8001 端口：

```powershell
cd "E:\视觉识别\Coal Mine Identification\go2_inspection"
.\.venv\Scripts\python.exe -m uvicorn app.api:app --host 0.0.0.0 --port 8001
```

此时打开 `http://127.0.0.1:8001/ui`。

### 11.3 提示缺少 FastAPI、Pillow、python-docx 或 OpenCV

正常情况下启动脚本会自动修复。若网络或软件源异常导致自动安装失败，可在网络恢复后
手动重新安装运行依赖：

```powershell
.\.venv\Scripts\python.exe -m pip install -r E:\视觉识别\Coal Mine Identification\go2_inspection\requirements-runtime.txt
```

### 11.4 上传成功但没有识别目标

先检查控制台“推理模式”状态，或检查 `/health` 中的 `inference_mode`、`detector`
和 `detector_configured`。

- `noop`、`false`：当前未加载模型，只会保存图片和任务记录；
- `ultralytics`、`true`：模型已加载，需要继续检查类别映射、置信度和图片质量。

### 11.5 metadata.json 上传失败

重点检查：

- JSON 格式是否正确；
- 图片数量和文件名是否与 `images` 一致；
- 抓拍 ID 是否已被其他不同任务使用；
- 时间是否为 ISO-8601 格式；
- 工位和相机字段是否为空。

### 11.6 参数保存后旧结果没有变化

这是预期行为。参数只对新任务立即生效；请选择旧任务并点击
“按当前参数重新处理”。
